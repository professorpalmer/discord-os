## 2. Minimal Bot sketch (one Card/Page/TabBar message)

A Page is sent in response to an interaction; it builds a `discord.ui.LayoutView`.
Callbacks should rebuild the page and edit the same message.

```py
import discord
from discord.ext import commands
from kagekit import Card, Page, Tab, TabBar, Text

bot = commands.Bot(command_prefix="!", intents=discord.Intents.default())

async def render(interaction: discord.Interaction, active: str):
    async def change_tab(i: discord.Interaction, value: str):
        await render(i, value)             # replace, do not stack a new message

    page = Page(
        tabs=TabBar(
            tabs=[Tab("One", "one"), Tab("Two", "two")],
            active=active,
            on_change=change_tab,
        ),
        body=[Card(title="KageKit spike", intent="brand",
                   children=[Text(f"Active tab: {active}")])],
    )
    if interaction.response.is_done():
        await page.edit(interaction)
    else:
        await page.send(interaction, ephemeral=False)

@bot.tree.command(name="kagekit_spike")
async def kagekit_spike(interaction: discord.Interaction):
    await render(interaction, "one")

# In production, sync bot.tree in setup_hook/on_ready as appropriate.
bot.run("TOKEN")
```

`Page.send()`/`Page.edit()` handle the Components V2 response restriction. A direct
`page.build()` is also available when the caller needs the LayoutView.

## 3. Gotchas: custom IDs and LayoutView

- LayoutView is not classic `discord.ui.View`; V2 items cannot be put in `View`.
  A V2 message cannot include `content`, `embed`/`embeds`, or attachments in the same
  payload. Use `Text`/`Heading`/`Card` instead. KageKit's interaction helpers defer
  and follow up for V2 sends, and clear content/embed/attachments when editing.
- Converting/editing an existing V2 message requires `LayoutView`; discord.py's
  `LayoutView.from_message()` is the relevant path. Do not use `View.from_message()`.
  If changing a classic message to V2, clear its old body explicitly; prefer
  `Page.edit()`/`ComponentBuilder.edit_interaction_response()`.
- Existing stable IDs are supported on `Action.custom_id` and `Select.custom_id`, and
  at the low layer (`ComponentBuilder` button/select `custom_id`). `Control(item=...)`
  is the escape hatch for a prebuilt `discord.ui.Item`/custom callback. `SettingRow`
  does not expose an accessory custom_id; use low-level builder/Control if that matters.
  TabBar/Pager generated controls have no public custom_id parameter.
- Never duplicate custom IDs in one view. Omitted IDs are generated by discord.py;
  rebuilding a page therefore changes them. That is fine for ordinary live callbacks,
  but not for restart-safe persistent routing. For persistence, supply stable IDs on
  every interactive item, use `timeout=None`, and register the view after restart;
  verify KageKit-generated TabBar/Pager IDs meet your persistence needs (otherwise
  hand-build those rows).
- In LayoutView, classic buttons/selects must be in explicit `ActionRow`s; KageKit's
  `Control` path does this. Selects always consume their own row.
- Budget is checked before send: <=10 top-level components, <=40 total components,
  <=5 buttons/action row, and V2 text total <=4000 display characters. More than five
  tabs automatically becomes a select. `LimitError` is raised for KageKit's checked
  budgets.
- `Page` is declarative and opinionated: tabs top-level, cards in body, pager row,
  message-wide actions bottom; interactions edit the same message.

## 4. Adopt vs fallback (hand LayoutView + discord-pager)

**Adopt KageKit if all spike gates pass:**

1. Runtime can move to Python 3.11+ and discord.py 2.7+.
2. The surface can be a Components V2-only message (no simultaneous content/embed),
   fits Discord budgets, and the prescribed Page/Card/tab/pager layout is acceptable.
3. A live test proves initial send, tab switch, pager/modal jump, callback response,
   same-message edit, and expected custom-ID dispatch.
4. Existing persistent/custom-ID interactions either map to `Action`/`Select`/`Control`
   or are isolated behind a hand-built low layer; restart/reconnect behavior is tested.
5. Payload tests assert ordering, disabled active tab, IDs, and component count; no
   unacceptable beta (0.1.0) regressions or API gaps appear.

**Fallback to hand LayoutView + discord-pager if any gate fails:**

- Must stay on discord.py <2.7 or Python <3.11.
- Existing persistent IDs/views need exact control over every component, or need
  classic View/content/embeds mixed with the UI.
- Layout contract, generated IDs, 40/10-component limits, or same-message V2 behavior
  conflicts with the product; or required controls are not expressible by KageKit.
- Spike finds incompatibility/regressions in dispatch, restart persistence, modal
  paging, or message editing. Hand-build only the exceptional surface, or use the
  simpler hand LayoutView + `discord-pager` path for maximum control.

**Recommendation:** promising for new, structured V2 panels; treat 0.1.0 as beta and
keep a fallback for legacy/persistent custom-ID surfaces until the spike gates pass.
